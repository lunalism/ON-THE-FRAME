# A-010 프리뷰 경로 프레임 0 불일치 — 진단 요약

> 상태: **미해결(원인 미확정)**, 2026-10-10. 무시되는 빌드 폴더(`app/.build/test-work/diagnostics/`)의 원시 기록이 지워져도 남도록 핵심 증거만 옮겼다. 개인 경로·개인 미디어는 없다. 상세 설명은 [app/README.md](../../app/README.md) §12.

## 현상

- 테스트: `InputCompatibilityTests.testNonThirtySourcesEditExportAndPreview`(생성 fixture 5개의 섞인 타임라인)
- 프리뷰 경로(AVPlayerItem + AVPlayerItemVideoOutput) 타임라인 프레임 0의 기대는 `id71#10`이다. 25 fps 원본 `otf-P25.mp4`의 원본 시각 13/30 s에 표시 중인 프레임이다.
- 재현된 3회에는 `id71#29`를 받았다(블록 PSNR 23.1 dB). 내보낸 파일은 매번 통과했다.
- 이 기본 합성기 경로 문제는 E2 사용자 정의 합성기 문제와 따로 다룬다(원인이 같다고 보지 않음).

## 확인된 사실

1. composition 원본 시각 대응은 맞다. 독립 경로 세 가지가 모두 `id71#10`이었다.
   - 원본 파일 독립 디코딩(AVAssetImageGenerator, 허용 오차 0, 13/30 s)
   - composition 오프라인 렌더(AVAssetReaderVideoCompositionOutput, 프레임 0)
   - 내보낸 파일 디코딩
2. 관찰자의 나중 읽기, 덜 끝난 탐색, 다른 플레이어 항목은 원인이 아니다(재현 2·3의 기록).
3. `#29`는 `otf-P25.mp4`의 다음 동기(키) 프레임이다. 동기 프레임은 #0·#29이고, 요청한 #10은 #0부터의 GOP 안에 있다. 디코딩 순서 덤프로 확인했다.
4. 세 번 모두 같은 화소 지문이었다. 무작위 손상이 아니라 매번 같은 화면이다.

## 가설(확인되지 않음)

- 새 플레이어 항목의 첫 정밀 탐색에서 프리뷰 출력이 다음 키프레임의 디코딩 버퍼를 요청 시각 표시로 넘겼다.
- 이것이 뒤에 정확한 버퍼가 따로 오는 임시 버퍼인지, 앱 화면(AVPlayerLayer)에도 보이는지는 확인되지 않았다.

## 정해진 범위의 후속 조사(재현 없음)

- 시도: 새 프로세스 12회
  - 1회: 앱 레이어 진단 단독
  - 11회: 엔진 전체 실행 + 같은 시간대의 앱 레이어 진단
  - 엔진: 프리뷰 받기마다 뒤따르는 버퍼를 0.5초 동안 기록했다(판정은 늘 첫 버퍼).
  - 앱: 원래 실패 타임라인을 일반 재구성 경로(새 항목 → 교체 → 재생 헤드 0 정밀 탐색)로 올렸다. 첫 탐색 완료 뒤 1.5초 동안 비디오 출력과 `AVPlayerLayer.displayedPixelBuffer()`를 따로 기록했다. 레이어 확인은 일시정지 상태에서만 했다. 프로세스마다 새 항목 3개다.
- 결과:
  - 엔진 엄격 검사: 11회 모두 실패 0
  - 앱: 33개 새 항목 모두 출력·레이어 첫 화면이 `id71#10`
  - 앱 첫 항목의 첫 출력 버퍼는 탐색 완료 뒤 132–489 ms에 왔다. 이후 항목은 12–34 ms였다.
- 결론: 두 질문(뒤이은 정확한 버퍼 여부, 앱 레이어 표시 여부) 모두 이번 범위에서 답하지 못했다. 재현이 없었다고 해결된 것은 아니다.

## 남은 위험과 다음 단계(제안)

- 엄격한 프리뷰 검사는 그대로 두어 가끔 실패할 수 있다. 실패하면 `PreviewProbe.Record`가 실패 메시지에 들어간다.
- 진단 실행 방법:
  - `OTF_PREVIEW_DIAG=1`: 진단 테스트
  - `OTF_DIAG_FOLLOWUP=초`: 뒤따르는 버퍼 기록
  - `app/scripts/layer-diag.sh`: 앱 레이어
- 재현되면 같은 기록으로 두 질문에 답할 수 있다. 임시 버퍼로 확인되면 근거와 함께 하네스의 받기 규칙을 바꾼다. 앱 레이어에서 잘못된 화면이 확인되면 앱 결함으로 다룬다.
