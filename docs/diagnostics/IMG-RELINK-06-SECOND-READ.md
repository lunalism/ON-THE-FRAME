# IMG-RELINK-06 · 검증과 이미지 디코드 사이의 원본 변경

## 재현과 수정

생성 PNG A의 probe와 descriptor 비교가 끝나 가용성 true를 게시한 콜백에서 A를 이동했다. 제품 코드를 바꾸기 전 CP-14R 실행기와 단언을 그대로 다시 실행했다. 이전 Debug·Release 엔진 모두 계획 실패 뒤 통지가 [true]에 그쳐 exit 1이었다. 이전 매니페스트·해시와 실패 기록은 보존했다.

ImageIO가 URL을 다시 여는 단계에서 thumbnail을 얻지 못하거나 검증한 크기와 다르면, 같은 보안 범위에서 읽기 전용·nonblocking으로 URL을 열고 그 파일 디스크립터의 장치·inode·크기·수정 시각을 비교한다. 이미지 바이트를 한 번 더 디코드하지 않는다. 열린 디스크립터는 모든 경로에서 닫는다. 디코드가 성공해도 버퍼에 그린 뒤 URL의 식별값을 다시 비교하고 나서 업로드한다.

| 확인한 사실 | 프리뷰와 가용성 처리 |
|---|---|
| 경로 없음 또는 상위 경로가 디렉터리가 아님 | 원본 누락 오류, 해당 UUID에 false |
| OS가 읽기 접근을 거부함 | 접근 권한 오류, 해당 UUID에 false |
| 검증 시점과 다른 파일·크기·수정 시각 | 원본 변경 오류, 해당 UUID에 false |
| 같은 파일을 다시 열 수 있으나 ImageIO가 이미지를 반환하지 못함 | 디코드 오류, 마지막 원본 가용성 유지 |
| 색 공간·픽셀 버퍼 준비 실패 또는 합성기 자원 오류 | 프리뷰 오류, 누락 통지 없음 |
| 다른 OS 오류로 원본 상태를 확정할 수 없음 | 확인 불가 오류와 errno, 마지막 원본 가용성 유지 |
| 취소 또는 이미 교체된 세션·세대·참조 | 이전 결과가 현재 행이나 프리뷰 오류를 변경하지 않음 |

프리뷰 계획이 실패하면 새 프레임을 설치하지 않는다. 목록은 기존 missingMedia, 프리뷰 메시지는 기존 imagePreviewError를 사용한다. 파일시스템 감시, 저장 descriptor, 스키마, 렌더러 수식 및 scope 소유권은 변경하지 않았다.

## 증거 해석

원래 CP-14R 실행기의 정상 및 디코드 경계 시퀀스와 새 XCTest를 구분한다. XCTest는 실제 이동, 잘못된 바이트의 원자적 교체, 같은 바이트이나 inode가 다른 원자적 교체, 생성 파일의 읽기 권한 제거, 검증 통지에서의 취소를 사용한다. 유효한 파일의 디코더 거부는 파일을 변조하지 않고 테스트에서 thumbnail 함수가 nil을 반환하도록 했다. 자원·불확실 오류는 가용성 분류를 검사했으며 시스템 메모리 고갈이나 실제 외장 볼륨 장애를 유발하지 않았다.

서명 앱 자체 검사는 같은 가용성 콜백에서 생성 파일을 이동해 실제 편집기 행을 캡처하고 AVPlayerLayer 표시 버퍼를 검사한다. 일반 재연결 Undo/Redo, A 원위치 복구, 초기 누락 프로젝트, 새 세션 열기, 오래된 결과 및 다른 이미지 보호도 기존 검사에 포함한다. 이번 소유자 마우스 검사는 별도로 수행하지 않았다.

수정 전 Debug·Release 원래 단언은 각각 exit 1, 수정 후에는 같은 단언에서 [true,false]와 계획 실패를 관찰해 각각 exit 0이었다. 일반 이동→B 재연결→Undo→Redo→A 복구 순서도 두 구성에서 exit 0이었다. 집중 엔진 검사는 각각 50/50, 별도 미검증 이미지 내보내기 거부 검사는 각각 1/1로 각 구성 합계 51개, 실패·건너뜀 0, exit 0이었다. 서명 앱의 영상·소리 패널 19/19 및 일반 편집 단축키 44/44도 통과했다. 최초 Debug 빌드는 디코드 크기 변수의 범위 오류로 테스트 전에 실패했다. 검증된 descriptor의 표시 크기를 쓰도록 바로잡은 뒤 성공했으며 첫 로그도 보존했다.

최종 서명 앱은 71/71, scope 획득/해제 12/12, 드라이버 exit 0, 시간 초과 없음이었다. 세션 0에서 같은 미디어 UUID의 세대 2는 missing=true·원본 누락 오류·빈 플레이어와 빈 표시 버퍼·‘재연결…’ 경고 행, 세대 3은 복구된 원본·missing=false·오류 해제·레이어 RGB (254,39,1)·‘교체…’ 일반 행이었다. 원본 상태와 실제 행 캡처는 app/selftest-work/img-relink06-01/final에, 수정 전후 단언은 같은 증거 루트의 before 및 after에 따로 보존했다.

이 판정은 검사 순간의 OS 응답과 기존 파일 식별 계약에 한정한다. 이후 파일이 다시 이동할 수 있으며, OS 전체의 권한 변화나 모든 동시 파일 변경을 보장하지 않는다. CP-14 및 CP-14R의 게시 보류 매니페스트와 해시 장부는 역사적 기록이며 게시 전에는 새 감사가 필요하다.
