# IMG-RELINK-05 · 열린 세션에서 이동한 원본의 가용성 복원

## 수정 전 재현

생성 PNG A를 가져와 빨간 프레임을 확인한 후 파일을 이동하고 기존 타임라인 재구성을 실행했다. JPEG B로 재연결해 초록 프레임을 확인하고 편집 메뉴의 Undo/Redo 항목을 프로그램으로 호출했다. 같은 세션에서 Undo 직후 원본 검증은 unreadable, 플레이어는 비어 있었지만 missingMedia에 해당 UUID가 없었고 실제 목록은 ‘교체…’를 표시했다. 처음부터 파일이 누락된 프로젝트를 연 경우와 분리했다. 수정 전 테스트 드라이버 exit 1과 행 캡처, 프레임 및 단계별 상태를 app/selftest-work/img-relink05-01/before에 보존했다.

## 상태 전파

- 기존 이미지 프리뷰 계획이 원본을 다시 읽고 probe 및 참조의 크기·수정 시각·descriptor를 검증한다. 그 원본별 결과를 편집기 세션에 전달한다. 이중 probe를 수행하거나 프리뷰 실패 문자열을 분석하지 않는다. URL을 확보하지 못하거나 원본 검증·동일성 검사를 통과하지 못하면 해당 참조를 사용할 수 없다.
- 편집기는 취소 여부, 현재 프로젝트 세션, 프리뷰 세대, 미디어 UUID와 정확한 이미지 참조 revision을 검사한다. 일치하는 원본의 가용성과 해당 Undo 복원 정보만 갱신한다. 성공적으로 재검증한 원본은 다시 사용 가능해진다. 다른 미디어의 경고와 공용 상태 메시지는 보존한다.
- 합성기·GPU·재생 계획 오류는 원본 누락을 게시하지 않는다. 화면의 프리뷰 오류는 기존 세대별 imagePreviewError가 소유한다. 목록은 기존 missingMedia 조건을 그대로 사용한다. 원본 URL, 북마크, 보안 scope, 저장 형식, 편집 기록 자체는 가용성 게시로 변경되지 않는다.
- 이 동작이 실행되는 시점은 기존 프리뷰 재구성이다. 외부 파일을 상시 감시하지 않는다. 프리뷰 계획이 처음 실패한 원본에서 중단되면 아직 검사하지 않은 다른 원본의 상태는 그대로 둔다.

## 검증 구분

생성 원본의 경로·미디어 UUID·세션·세대·missingMedia·프리뷰 오류·플레이어 상태·프레임 값은 실행 폴더의 단계별 JSON에 기록한다. 행은 편집기 창에서 캡처한 PNG로 확인한다. 메뉴 항목 호출 및 합성 키와 소유자 마우스 조작을 구분한다. 파일이 처음부터 누락된 프로젝트의 열기, 후보 취소·거부, 교체·저장 및 같은 프로세스의 새 세션 열기는 별도 단계다.

최종 서명 Debug 앱은 66/66, scope 획득/해제 12/12, 드라이버 exit 0, 시간 초과 없음이었다. 세션 0에서 같은 미디어 UUID 0314AD7C-9000-4233-865F-05D298CACD7E를 유지했다. 세대 1/2/3/4/5/10은 A 가져오기/이동/B 재연결/Undo/Redo/A 반환 후 Undo다. 실제 AVPlayerLayer 중앙 sRGB 표본은 각각 (254,39,1)/표시 버퍼 없음/(2,248,2)/없음/(2,248,2)/(254,39,1)이었다. 같은 여섯 화면의 행 캡처에서 교체/재연결/교체/재연결/교체/교체 버튼과 경고 색을 확인했다. 전체 원본 경로와 단계별 값은 final 폴더 JSON에 남겼다.

현재 참조와 다른 revision 및 지난 세대·세션의 검증 결과를 적용 경계에 직접 전달해 거부를 확인했다. 별도로 준비가 끝난 실제 비동기 프리뷰 계획을 보류한 뒤 프로젝트를 교체하고 재개해, 늦은 결과가 빈 프로젝트에 게시되지 않음을 확인했다. 이미지 두 개 중 하나만 옮긴 경우 해당 UUID만 누락으로 바뀌었고 파일 복구 후 재검증됐다. 중간 실행에서는 이동·Undo·복구 단계가 통과한 뒤 다중 이미지 fixture 삽입이 기존 클립과 겹쳐 실패했다. 원래 결과를 유지하고 두 번째 이미지를 타임라인 끝에 배치한 뒤 전체 검사를 다시 실행했다.

이번 Debug/Release 엔진 회귀는 각각 45/45, 실패·건너뜀 0, 각 exit 0이었다. 서명 앱 별도 영상·소리 패널 19/19 및 일반 클립·텍스트 단축키 44/44도 통과했다. strict/deep 서명 확인 exit 0. 소유자 마우스 재검사는 이번 실행에 포함하지 않았다.

IMG-CP-14의 BLOCKED 기록, 당시 16개 경로 목록 및 SHA-256 장부는 역사적 증거다. 이번 소스에는 적용되지 않으며 게시 전 새 체크포인트 감사와 해시 매니페스트가 필요하다.
