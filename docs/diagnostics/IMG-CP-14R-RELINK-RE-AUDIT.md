# IMG-CP-14R · 이미지 재연결 최종 재감사

**BLOCKED.** 이전 CP-14에서 지적한 순서는 수정됐다. 같은 프리뷰 계획 안에서 원본 probe와 디코드 사이에 파일이 이동하면 가용성 결과와 프리뷰 결과가 다시 갈라진다. 이번 감사에서 제품 및 테스트 소스를 수정하지 않았다.

## 두 재현의 차이

| 원본 이동 시점 | 최종 코드의 실제 결과 | 판정 |
|---|---|---|
| A를 이동한 뒤 프리뷰 재검증 시작 | A 누락 → B 정상 → Undo 시 A 누락 → Redo 시 B 정상 → A 반환 후 Undo 시 A 정상 | 이전 차단 사유 해소 |
| A의 probe가 성공해 true를 게시한 직후, 디코드용 ImageIO가 같은 URL을 다시 열기 전 | 파일은 이동했고 계획은 디코드 오류로 끝났으나 가용성 통지는 [true] 하나뿐 | 새 차단 사유 |

새 재현은 최종 Debug 및 Release 엔진 객체에 별도의 일회용 진단 실행기를 연결했다. 각각 정상 시퀀스를 먼저 수행하고, 현재 엔진의 원본 가용성 콜백에서 생성 PNG 사본을 이동시켜 외부 이동 시점을 고정했다. 두 구성 모두 계획 실패와 마지막 true를 관찰해 가용성 단언이 exit 1이었다. 진단의 실제 파일 이동은 생성 사본에만 적용했다.

InternalImagePreview.build는 descriptor·크기·수정 시각 비교 뒤 true를 게시한 다음 URL을 다시 디코드한다. 두 번째 읽기 자체가 실패하면 최종 FileIdentity 비교와 false 게시까지 도달하지 않는다. ProjectStore의 세션·세대·revision 검사는 낡은 결과를 거르지만 이 경우에는 한 세대와 한 참조 안에서 발생한다. catch는 imagePreviewError만 설정하고 MediaListView는 missingMedia로 경고와 ‘재연결…’ 또는 ‘교체…’를 선택한다. 이 경계에서의 잘못된 목록 상태는 엔진 통지와 최종 앱 코드를 대조한 판단이다. 이 경계 자체의 서명 앱 화면은 촬영하지 않았다. 파일 감시기를 추가해야 한다는 요구는 아니며, 이미 진행 중인 재검증이 내보낸 결과의 일관성 문제다.

## 재실행한 검증

- 전용 APFS 캐시, 단일 작업, 기존 메모리·시간 제한에서 관련 엔진 45개를 Debug와 Release로 각각 실행했다. 모두 통과, 실패·건너뜀 0, 각 exit 0.
- 별도 엔진 실행기에서 A 가져오기·이동·B 재연결·Undo·Redo·A 복구와 동일 클립 보존은 두 구성 모두 exit 0. 위 추가 경계 검사는 양쪽 모두 exit 1. 실행기와 원시 로그는 로컬 감사 증거에만 있다.
- 보존된 RELINK-05 최종 Debug 앱을 strict/deep 서명 검증한 뒤 새 생성 fixture 및 격리 suite로 실행했다. 66/66, scope 12/12, 드라이버 exit 0, 시간 초과 없음. 같은 세션 세대 4에서 Undo는 경고·‘재연결…’·표시 버퍼 없음, 세대 5에서 Redo는 정상 행·‘교체…’·레이어 중앙 RGB (2,248,2), 세대 10의 A 복구는 (254,39,1)이었다. 새 창 캡처와 실제 AVPlayerLayer 측정을 대조했다.
- Swift 구문, Xcode 프로젝트 메타데이터, 후보 텍스트·모드·경로, 새 문서 링크, diff 공백을 검사했다. 앱 재빌드나 차단된 자막·스펙트럼·WMO 진단 컴파일은 수행하지 않았다.

## 결합 구현과 증거 범위

내부 빌드·런타임 게이트와 기존 JPEG/PNG probe 제한을 유지한다. 치수·방향 변경 확인 및 재검증 후 같은 프로젝트·미디어·클립 UUID와 편집·변형을 유지해 교체한다. 확인 중 표시·취소·후보 실패, 같은 치수와 교차 형식, 북마크와 원본별 scope, 저장/복원 및 새 URL의 프리뷰·내보내기를 확인했다. 키보드와 메뉴의 편집 기록, 별도 프리뷰 오류, 비동기 취소·세대/세션/revision 검사, 가용성의 Undo 바인딩 갱신이 연결되어 있다. 검사 시점은 기존 프리뷰 재검증이며 파일시스템 상시 감시는 없다.

RELINK-02에서 소유자가 네이티브 재연결·치수 변경 승인·저장·종료·별도 프로세스에서 다시 열기·내보내기를 수행했다. 당시 마우스 Undo 실패와 오래된 오류 표시도 보존했다. 이후 소유자가 RELINK-03 수정판에서 마우스 메뉴 Undo/Redo 성공을 보고했다. RELINK-04/05 자동 재열기는 같은 프로세스의 새 세션이다. 별도 BOOKMARK-01의 프로세스 간 시험은 이전 근거이며 RELINK-05 또는 이번 감사의 새 소유자 수동 시험이 아니다. RELINK-05의 서명 패널 19/19 및 단축키 44/44는 재사용 증거다.

원래 파랑 G < 40 검사는 51로 실패했다. 원본 PNG sRGB (4,51,255), MP4 복원값 (4,51,252/253/253)이었다. 독립 BT.709 video-range 평탄부 기준과 합성기 raw Y/Cb/Cr는 파랑 (60,224,102), 노랑 (216,18,140)으로 일치했다. MP4는 첫 프레임 Cb만 −1/+1이고 나머지는 일치했다. 원래 실패와 수정 측정을 별개로 보존했다.

## 후보와 제한

[새 후보 목록](IMG-CP-14R-MANIFEST.txt)은 실제 최종 작업 트리에서 산정한 20개 경로다. 자신의 해시를 포함하는 순환을 피하기 위해 목록 자체와 이 보고서를 포함한 20개 전부의 SHA-256·Git mode·경로는 별도 로컬 장부 app/selftest-work/img-cp14r-01/candidate-sha256.tsv에 보존한다. 새 후보도 게시 보류다. 기존 [CP-14 차단 보고서](IMG-CP-14-RELINK-AUDIT.md)와 [당시 16개 목록](IMG-CP-14-MANIFEST.txt), 당시 해시 장부는 역사적 증거로 유지한다.

공개 이미지 게이트는 꺼져 있다. 8 MiB·2048 px 내부 제한, 장기 세션의 scope 보유, 외장 볼륨·OS 권한 변화, 고해상도 이미지는 별도 검증이 필요하다. 스펙트럼 Stage 3C-2와 Stage 4는 미구현이다. 다음 작업은 두 번째 읽기가 실패할 때 현재 원본의 소실·교체를 확인해 해당 참조의 가용성을 정정하고, 일반 디코더·자원 오류는 별도로 유지하는 회귀 검증이다.
