# 편집기 UI 첫 계획 — ON THE FRAME

> **상태: 제안(미승인), 2026-10-10 작성.** 기준 커밋 `06b0ebf`. M1은 작업 승인 A-005~A-009로 구현해 2026-10-10 완료했다(§3 완료 기준 대조). 구현 내용·검증·한계와 완료 판단은 [app/README.md](../app/README.md)에 있다(이 계획의 제안 항목 자체를 승인한 것은 아니다). 이 문서는 첫 대화형 편집기 화면과 첫 마일스톤(M1)의 계획이다.
> - M1 밖의 앱 코드(M2 이후)는 승인되지 않았다. 착수하려면 별도 작업 승인과 [CLAUDE.md](../CLAUDE.md) 단계 규칙 갱신이 필요하다.
> - UI 기술, 배포 대상(최소 macOS), 배포 정책, 프로젝트 파일 포맷을 확정하지 않는다(O-01, O-06, O-08, P-003, P-004).
> - **소유자 방향(2026-10-10):** 편집기 UI 작업을 엔진 검증과 나란히 시작한다. 장시간 실험(E3-2 이후)을 모두 끝내는 것이 UI 개발의 전제가 아니다. E2의 해결되지 않은 소스 프레임 불일치와 남은 성능 질문은 열린 상태로 둔다.
> - 4K 일반 지원·3시간 지원을 주장하지 않는다. 검증된 범위는 시험한 Mac 한 대의 짧은 FHD(E1), 10초 4K(E2, 미완료), 10분 FHD(E3-1)뿐이다.

## 1. 화면 배치

```
┌───────────────────────────────────────────────────────────────────────────┐
│ [프로젝트 이름]                         [가져오기]           [내보내기]      │  위: 툴바
├──────────────┬─────────────────────────────────────────┬──────────────────┤
│ 미디어        │                                         │ 속성(인스펙터)    │
│ ▸ 영상        │               프리뷰                      │ 선택한 클립:      │
│ ▸ 이미지      │                                         │  원본, 소스 구간, │
│ ▸ 오디오      │                                         │  타임라인 위치,   │
│ (썸네일·길이) │  ◀◀  ▶/❚❚  ▶▶   00:01:23:14 / 00:10:00:00 │  길이             │
├──────────────┴─────────────────────────────────────────┴──────────────────┤
│ 눈금자  |0s     |5s     |10s    |15s     ▼ 재생 헤드                        │
│ 영상     [ A 클립 ][ C 클립   ][ B ]                                          │  아래: 타임라인
│ 오디오   [ A 소리 ][ C 소리   ][ B ]   (영상에 연결된 소리)                    │
│ 자막     (M2 이후)                                                          │
│ 스펙트럼  (M2 이후)                                                          │
└───────────────────────────────────────────────────────────────────────────┘
```

- **위(툴바):** 프로젝트 이름, 가져오기, 내보내기. M1에는 저장이 없으므로 프로젝트 이름은 표시용이다.
- **왼쪽(미디어):** 가져온 자산 목록. 영상·이미지·오디오 그룹을 둔다. M1은 영상만 가져온다. 이미지·오디오 그룹은 자리만 있고 비활성으로 "M2 이후"라고 표시한다(R-01을 지우지 않음).
- **가운데(프리뷰):** 실시간 합성 프리뷰. 재생/일시정지, 프레임 이동, 재생 헤드 시간 표시, 전체 길이.
- **오른쪽(속성):** 선택한 대상의 속성.
  - M1에서는 영상 클립의 원본 이름, 소스 구간(in/out), 타임라인 위치, 길이를 읽기 전용으로 보여 준다.
  - 자막·스펙트럼 속성은 M2 이후다.
- **아래(타임라인):** 영상, 오디오, 자막, 스펙트럼 레인.
  - M1은 영상 레인과 그 영상에 연결된 오디오 레인만 편집한다.
  - 자막·스펙트럼 레인은 자리만 보이고 비활성이다.

## 2. 타임라인 조작 (M1 기본값)

| 조작 | 동작 | 단축키·제스처 |
| --- | --- | --- |
| 선택 | 클립을 클릭하면 그 클립이 선택된다(M1은 한 번에 하나). 빈 곳을 클릭하면 선택 해제 | 클릭, Esc |
| 재생 헤드 | 눈금자를 클릭하거나 끌면 이동한다. 프레임 격자에 맞춘다. 재생 중 클릭하면 그 위치로 탐색하고 재생은 계속된다 | 클릭·드래그, ←/→ 1프레임, Home/End |
| 분할 | 재생 헤드 위치에서 선택한 클립을 나눈다. 선택이 없으면 재생 헤드 아래 클립을 나눈다. 재생 헤드가 컷 경계나 클립 밖이면 아무것도 하지 않고 상태 표시줄에 알린다 | ⌘K(소유자 결정 D-019로 ⌘B에서 바꿈) |
| 트림 | 클립 왼쪽·오른쪽 가장자리 손잡이를 끈다. 원본 범위 안에서만, 최소 1프레임. 뒤 클립들은 따라 움직인다(리플 트림) | 가장자리 드래그 |
| 이동 | 클립을 끌어 다른 클립 사이에 놓는다. 삽입 위치를 세로선으로 보여 준다. 나머지는 빈틈 없이 다시 이어진다 | 드래그 |
| 삭제 | 소유자 결정 D-020으로 바뀜: Delete는 선택한 클립을 지우고 빈틈을 남기고(다른 클립 위치·길이 그대로), ⇧Delete는 빈틈을 닫는 리플 삭제다. 원본 파일은 건드리지 않는다 | Delete, ⇧Delete |
| 실행 취소·다시 실행 | 위 편집과 클립 배치를 하나씩 되돌린다. 드래그 하나는 한 단계다. 선택과 재생 헤드 이동은 실행 취소 대상이 아니다 | ⌘Z, ⇧⌘Z |
| 배치 | 미디어 목록에서 타임라인으로 끌어 놓거나, "타임라인 끝에 추가"를 쓴다 | 드래그, ⌘E(제안) |

**정해지지 않은 편집 의미와 권장 기본값**(M1은 아래 기본값으로 하고 바꿀 수 있게 둔다):

| 질문 | 권장 기본값(M1) | 이유 |
| --- | --- | --- |
| 빈틈을 허용하는가 | 허용하지 않는다. 영상 트랙 1개에 클립이 빈틈 없이 이어진다(리플) | 검증된 엔진 모델(E2·E3의 순차 하드 컷)과 같다. 빈틈·겹침·여러 트랙은 다음 마일스톤 |
| 영상의 자체 소리 | 영상과 연결되어 함께 트림·이동·삭제된다. 분리는 다음 마일스톤 | E2·E3 composition 구성과 같음 |
| 프레임레이트가 다른 원본 | 타임라인은 30 fps(M1 고정, 제안). 원본 시각은 유리수로 저장하고 타임라인 프레임으로 맞춘다 | E2 수정(프레임 타이밍 = 비디오 트랙)은 30 fps 원본에서만 확인했다. 다른 프레임레이트는 **위험 항목**(§4.3) |
| 끝 위치 | 마지막 유효 프레임을 유지(D-018) | 확정 결정 |
| 재생 중 편집 | 편집 제스처를 시작하면 재생을 멈춘다. 자동으로 다시 재생하지 않는다 | 단순하고 예측 가능 |
| 내보내기 중 편집 | 허용. 내보내기는 시작 시점의 타임라인 사본을 쓴다 | 편집과 내보내기의 독립 |
| 실행 취소 뒤 선택 | 되돌린 편집이 영향을 준 클립을 선택한다. 그 클립이 없어졌으면 선택을 해제한다 | 사용자가 결과를 바로 볼 수 있음 |
| 빈 타임라인 | 프리뷰는 빈 화면과 안내 문구, 내보내기 버튼 비활성 | 엔진은 빈 타임라인을 거부함 |
| 기존 파일로 내보내기 | 저장 패널에서 사용자가 "대치"를 확인한 경우만 허용한다. 같은 볼륨의 임시 파일에 쓰고 검증한 뒤 원자적으로 바꾼다. 취소·실패 시 기존 파일은 그대로 | DR-10. 실험 엔진은 기존 대상을 항상 거부하므로 바꿔야 함 |

## 3. 첫 마일스톤(M1) 범위와 완료 기준

**범위:** 영상 가져오기 → 클립 배치 → 선택·분할·트림·이동·삭제 → 실행 취소·다시 실행 → 프리뷰 → 내보내기.
- 가져오기: 열기 패널과 끌어 놓기. M1이 시험하는 형식은 H.264/HEVC MP4·MOV다. 지원 포맷 정책(O-03)은 미정이다.
- 내보내기: 타임라인 설정(M1 제안: 1920×1080, 30 fps, SDR, H.264 + AAC, MP4)으로 내보낸다. 진행률, 취소, 실패 안내, 출력 보호를 포함한다.

**M1에서 빼고 다음 마일스톤으로 넘기는 것(요구사항은 유지):**

| 항목 | 요구사항 | 마일스톤 |
| --- | --- | --- |
| 복사·붙여넣기 | R-02 | M2 (2026-10-11 타임라인 클립 복사·붙여넣기 구현, 커밋하지 않음 — [app/README.md](../app/README.md) §25) |
| 편집 가능한 자막(입력, 타이밍, 글꼴, 크기, 색, 정렬, 위치) | R-20, R-21 | M2 |
| 스펙트럼 소스 선택·컨트롤 | R-10~R-12 | M2 |
| 이미지·별도 오디오 가져오기와 배치 | R-01 | M2 |
| 프로젝트 저장·다시 열기 | R-41 | M3 |
| 누락 미디어 재연결 | R-42 | M3 |

마일스톤 번호는 제안이며 순서는 소유자가 바꿀 수 있다.

**완료 기준(M1):**
1. **원본 보존:** 가져온 원본 파일의 SHA-256이 편집·프리뷰·내보내기 전후로 같다(R-40).
2. **편집 모델:** 배치·분할·트림·이동·삭제와 각 동작의 실행 취소·다시 실행이 자동 테스트에서 독립 기대값(손으로 유도한 구간 표)과 같다.
   - 원본 범위 밖 트림, 컷 위치 분할, 빈 타임라인은 거부된다.
   - 여러 단계 실행 취소 뒤 다시 실행하면 원래 상태와 같다.
3. **프리뷰와 내보내기의 같은 해석:** 같은 타임라인 사본에서 만든 composition을 프리뷰와 내보내기가 함께 쓴다.
   - 자동 통합 테스트: 생성 fixture로 편집한 뒤, 내보낸 파일의 프레임 수, PTS, 컷 경계 양쪽 소스 프레임, 끝 프레임 유지가 기대값과 같다.
   - 오프라인 합성 출력과 프리뷰 합성 출력의 표본 지문이 같다(E2·E3 방법).
     - M1 적용(A-009): M1 내보내기는 H.264 손실 압축이라 비트 단위 지문을 요구하지 않는다. 대신 대표 프레임에서 (1) 원본 코드·검정 판정이 정확히 같고 (2) 16×16 블록 평균 PSNR ≥ 38 dB인지 본다. 허용치 근거와 대조는 [app/README.md](../app/README.md) §11.
4. **편집 뒤 프리뷰 갱신:** 편집 뒤 프리뷰가 같은 재생 헤드 시각에서 새 타임라인을 보여 준다. 자동 테스트에서 컷 경계 프레임을 비디오 출력 경로로 확인한다(성능 기준 없음).
5. **내보내기 처리:**
   - 진행률이 단조 증가한다.
   - 취소하면 대상 파일이 생기지 않고 임시 파일이 남지 않는다.
   - 실패 주입 시 원인 안내가 나오고 대상 파일이 생기지 않는다.
   - 기존 파일 대치는 확인한 경우에만, 실패 시 기존 파일이 보존된다.
6. **진단 분리:** 일반 화면에 실험 진단(타임라인 코드 칸, 소스 시각 검사 경고, 메모리 표본)이 보이지 않는다(§4.5).
7. **소유자 수동 확인:** 짧은 체크리스트(가져오기, 각 편집, 실행 취소, 프리뷰, 내보낸 파일 재생). 정성적 관찰로 기록한다.
8. **알려진 열린 문제를 문서에 남긴다:**
   - E2 소스 프레임 불일치
   - E3-1 관찰기 미전달 9프레임
   - 레이어 갱신 지연
   - 다른 프레임레이트 원본

## 4. 엔진 재사용과 필요한 변경

### 4.1 구성 요소 분류(현재 코드 기준)

| 구성 요소(위치) | 분류 | 앱에서 필요한 변경 |
| --- | --- | --- |
| `EditTimeline`(E2Core) — 클립 목록, 붙이기·트림·분할·이동, 구간 계산, `lastValidFrame` | **조정해서 재사용** | 클립과 미디어에 안정적 ID(UUID) 부여. 소스 키 문자열("A") 대신 미디어 ID로 참조. 타임라인 프레임 기준 분할·트림 연산 추가(가장자리 트림, 삭제). 30 fps 상수 대신 타임라인 설정 |
| `E2CompositionBuilder`(E2Core) — 편집 구간을 비디오 트랙 1개 + 클립 오디오 트랙으로 구성, 끝 유지용 보관 프레임, 프레임 타이밍 = 비디오 트랙 | **조정해서 재사용** | 원본을 미디어 ID → URL로 받음. 음악·자막·스펙트럼을 선택 사항으로(지금은 음악 필수). 해상도를 전역 `Spec4K` 대신 인자로 |
| `E2Compositor`, `E2Instruction`, `HeldFrame`(E2Core) — 실제 소스 프레임 복사 + 오버레이, 끝 유지, 소스 시각 검사 | **조정해서 재사용** | 원본 해상도·종횡비가 다를 때의 맞춤(M1 제안: 비율 유지, 레터박스). 소스 시각 검사는 남기되 결과는 진단 로그로만 |
| `Overlay`(E2Core) — 타임라인 코드 칸, 막대, 자막 | **일부 시험 전용** | 타임라인 코드 칸은 시험 전용이라 앱에서 끈다. 막대·자막 그리기는 M2에서 자막·스펙트럼 모델로 바꿔 재사용 |
| `E2Exporter`(E2Core) + `ExportControl`·`OutputGuard`(E1Core) — 입력 준비 시 공급, 취소·실패, 임시 → 검증 → 배타적 승격 | **조정해서 재사용** | 실험 예산 검사(`OwnedBudget`, 실험 디렉터리) 대신 여유 공간 사전 검사. 진행률 콜백을 UI용으로 공개. 대치 경로(원자적 교체) 추가. 임시 위치를 앱 권한 안으로(§4.4) |
| `SpectrumAnalyzer`·`SpectrumCache`(E1Core) | **M2에서 재사용** | 캐시 위치를 앱 캐시 디렉터리로. 분석은 백그라운드·취소 가능 |
| `FrameGrid`, `Hashing`, `Clock`, `Memory`(E1Core) | **그대로 재사용** | — |
| `SourceRef`(E1Core) — 내용 SHA-256 + 경로 | **조정** | 앱의 미디어 식별(§4.3)로 대체·확장 |
| `Spec4K`·`FrameLayout` 전역 배치 | **교체** | 프로세스 전역 설정 대신 프로젝트별 렌더 설정 값을 인자로 넘김(동시에 두 해상도 불가 문제 제거) |
| `SourceVideoSpec`·`AudioSynth`(생성 fixture), `E2Metrics`·`FrameTally`(픽셀 측정), `Expect2`·`Expect3`(독립 기대값), `Judge`, `Report`, `ResourceMonitor`, `Fingerprint`, 진단 모드(`diag-*`) | **시험 전용** | 앱 번들에 넣지 않는다. 엔진 패키지의 테스트·통합 테스트 대상으로 옮긴다 |
| 실험 실행기 창(`e2preview`·`e3preview window`) | **참고만** | 앱 UI가 대신한다 |

실험 코드는 그대로 두고, 필요한 부분을 새 엔진 패키지로 **복사·정리**하는 것을 권한다. 실험 증거의 재현성(소스 트리 해시)을 깨지 않기 위해서다.

### 4.2 편집이 프리뷰와 내보내기에 같은 방식으로 반영되는 경로

```
편집 명령 → ProjectDocument(값 타입 타임라인) 새 스냅샷 → CompositionPlanner(순수 함수)
          → { AVComposition, AVVideoComposition(합성기), 오디오 믹스 }
             ├─ 프리뷰: 새 AVPlayerItem으로 교체, 같은 재생 헤드 시각으로 정확 탐색
             └─ 내보내기: 시작 시점 스냅샷으로 따로 구성해 reader → writer
```

- 타임라인은 값 타입(불변 스냅샷)이다. 프리뷰와 내보내기는 같은 `CompositionPlanner`로 composition을 만든다. 실험에서 쓴 "같은 구성 함수" 원칙(E2·E3)이다.
- 편집마다 composition을 다시 만든다. 백그라운드 작업이고 세대 번호로 오래된 결과를 버린다. 연속 드래그는 놓을 때 한 번만 다시 만들고, 드래그 중에는 타임라인 그림만 갱신한다.
- 새 항목으로 바꾸는 동안 프리뷰는 마지막 화면을 유지한다.
- 내보내기는 시작 시점의 스냅샷을 복사해 쓴다. 이후 편집은 진행 중인 내보내기에 영향을 주지 않는다.

### 4.3 표현 방식

- **미디어 식별:** `MediaAsset { id: UUID, 북마크(앱 샌드박스 시 보안 범위 북마크), 표시 이름, 크기, 수정 시각, 내용 해시(백그라운드, 선택), 길이, 프레임레이트, 크기, 소리 유무 }`.
  - 큰 파일의 전체 해시는 가져오기를 막지 않도록 나중에 계산한다.
  - 재연결(R-42, M3)은 같은 식별 정보로 맞춘다(DR-08).
- **원본 시각 대응:** `Clip { id: UUID, mediaID, sourceIn(유리수 CMTime), duration(타임라인 프레임) }`. 타임라인 위치는 순서에서 계산한다(리플).
  - 대응식은 TECHNOLOGY-EVALUATION §3.3.2와 같다: 타임라인 `t` → 원본 `s_in + (t − t_start)`.
  - **위험:** E2 결함의 완화(프레임 타이밍 = 비디오 트랙)는 30 fps 원본에서만 확인했다. 다른 프레임레이트를 섞으면 출력 시각이 원본을 따를 수 있다. M1 자동 검사는 30 fps 원본으로 하고, 다른 프레임레이트는 주의 문구와 열린 질문으로 남긴다.
  - A-010(2026-10-10): 앱은 기본 합성기를 쓴다(사용자 정의 합성기·`sourceTrackIDForFrameTiming` 없음). 이 경로에서 29.97·25·23.976·59.94·가변 원본을 섞은 타임라인의 내보내기가 정확한 1/30 s 격자로 나오고, 원본 프레임·소리 위치가 시간 기준 기대값과 같음을 생성 fixture로 확인했다([app/README.md](../app/README.md) §12). 자막·스펙트럼을 위해 사용자 정의 합성기로 돌아가는 M2에서는 다시 확인해야 한다.
- **선택:** `Selection { clipID? }`와 `playhead(타임라인 프레임)`. 문서 상태(실행 취소 대상)와 분리한다.
- **실행 취소·다시 실행:** 편집 명령마다 이전·이후 타임라인 스냅샷을 `UndoManager`에 등록한다. 값 타입이라 클립 수에 비례하는 작은 비용이다. 드래그 하나는 한 단계로 묶는다. 자막·스펙트럼 편집도 같은 방식으로 들어온다(DR-02, M2).
- **취소:**

| 대상 | 방법 |
| --- | --- |
| 내보내기 | `ExportControl.cancel()` → 공급 중단, `cancelWriting`, 실험 소유 임시 디렉터리 정리 |
| composition 재구성 | Swift `Task` 취소 + 세대 번호 |
| 가져오기 분석(메타데이터·해시) | `Task` 취소 |
| 합성기 요청 | 기존 `cancelAllPendingVideoCompositionRequests` 규칙 |

### 4.4 실제 앱 번들이 바꾸는 것

- **미디어 접근:** 앱 샌드박스를 켜면 사용자가 열기 패널이나 끌어 놓기로 고른 파일만 읽을 수 있다. 다시 열 때는 보안 범위 북마크가 필요하다(M3 저장과 함께). 샌드박스를 켤지는 배포 방식(O-08, O-14)에 달려 있다. 개인 사용 단계에서는 꺼도 되지만, 나중에 켜면 접근 경로를 다시 손봐야 한다.
- **내보내기 임시 파일:** 실험 엔진은 대상과 같은 디렉터리에 임시 디렉터리를 만든다. 샌드박스에서는 저장 패널이 고른 파일만 쓸 수 있으므로 그 디렉터리에 바로 만들 수 없다. 대상과 같은 볼륨의 대치용 임시 디렉터리(`FileManager.url(for: .itemReplacementDirectory, …, appropriateFor:)`)를 쓰고, 원자적 교체로 바꾼다. 샌드박스 안에서의 동작은 M1에서 확인할 항목이다.
- **수명 주기:**
  - 앱 종료·창 닫기 중 내보내기는 확인 뒤 취소하고 정리한다.
  - 다음 실행 때 지난번에 남은 앱 소유 임시 디렉터리(고유 접두사)를 정리한다.
  - 재생 중에만 디스플레이 유휴 절전을 막는다(E3-1에서 디스플레이가 꺼지면 레이어 표시가 멈춘 것을 관찰함).
  - 백그라운드에서 재생 중이 아니면 assertion을 해제한다.
- **번들·서명:** 앱 번들, Info.plist, 서명이 필요하다. 개인 사용 단계의 서명 방식은 배포 결정(O-08)과 별개로 개발용 서명으로 시작한다.
- 실험의 창 모드(번들 없는 실행 파일의 `NSApplication`)에서 확인하지 못한 권한·메뉴·Dock 동작은 M1에서 처음 확인하게 된다.

### 4.5 진단을 일반 화면에서 빼는 방법

- 합성기의 소스 시각 검사, 요청 기록, 메모리 표본은 `os.Logger`(하위 시스템·범주별)로만 남긴다. 사용자 화면에 경고로 띄우지 않는다.
- 개발 빌드에만 숨은 "진단" 메뉴를 둔다. 요청 수, 불일치 수, 마지막 오류를 보는 작은 창이다. 릴리스 구성에서는 컴파일 조건으로 뺀다.
- 타임라인 코드 칸 같은 측정용 오버레이는 시험 전용 렌더 설정에서만 켠다. 앱 기본값은 끔.
- 판정·기대값·측정 코드는 엔진 패키지의 테스트 대상에만 있다.

## 5. 앱 구조와 UI 기술 제안(미승인)

**권장:** SwiftUI 앱 셸 + AppKit 타임라인·프리뷰 + 로컬 Swift 패키지(엔진).

```
ON THE FRAME.xcodeproj
├─ App(타깃): SwiftUI 창·툴바·미디어 목록·인스펙터·내보내기 시트, ProjectStore(@Observable), 편집 명령·UndoManager 연결
│   └─ AppKit 뷰(NSViewRepresentable): TimelineView(NSView + Core Animation 레이어), PreviewView(AVPlayerLayer 호스트)
└─ Packages/OnTheFrameEngine(로컬 Swift 패키지)
    ├─ TimelineModel   — 클립·미디어 ID, 편집 연산(순수, 테스트 쉬움)
    ├─ CompositionPlanner, Compositor — 프리뷰·내보내기 공유 구성(E2Core에서 정리해 가져옴)
    ├─ ExportService   — 내보내기·출력 보호·취소(E1Core·E2Core에서)
    ├─ MediaLibrary    — 가져오기·메타데이터·식별
    └─ Tests           — 편집 연산 단위 테스트, 생성 fixture 통합 테스트(실험의 기대값·측정 방법 재사용)
```

**이유:**
- 인스펙터·목록·시트·툴바는 SwiftUI가 빠르고 단순하다.
- 타임라인은 정밀한 마우스 처리(손잡이, 커서, 끌기, 스냅)와 많은 항목 그리기가 필요해 AppKit/Core Animation이 더 예측 가능하다.
- 프리뷰는 실험에서 검증한 `AVPlayerLayer` 경로를 그대로 쓴다.
- 엔진을 앱과 분리한 패키지로 두면 UI 없이 테스트할 수 있다(실험 방식 유지).

**대가:**
- SwiftUI–AppKit 연결 코드가 생긴다.
- SwiftUI 기능은 최소 macOS 버전에 묶인다. P-004는 잠정 macOS 15를 제안했지만 미승인이다.
- 순수 AppKit은 연결 코드가 없지만 코드량이 많다. 순수 SwiftUI는 타임라인 성능과 정밀 조작에서 위험이 크다.

이 제안은 방식 A(Swift + AVFoundation, P-003)를 전제로 한다. P-003을 승인하는 것이 아니다.

**문서 구조:** M1은 창 하나에 메모리 안 프로젝트로 시작한다. 모델은 저장 형식과 무관한 값 타입으로 두어, M3에서 문서 기반(NSDocument 또는 SwiftUI `DocumentGroup`, 자동 저장, 실행 취소 연결)으로 옮기기 쉽게 한다. 파일 포맷(O-06)은 M3 전에 정한다.

## 6. 구현 순서(제안)

0. **승인:** 앱 코드 작업 승인(새 작업 승인 ID), CLAUDE.md 단계 규칙 갱신, §7의 선택.
1. **엔진 패키지:** E1Core·E2Core의 필요한 부분을 복사·정리한다.
   - 전역 배치 대신 렌더 설정 인자
   - 음악·자막 선택 사항
   - 실험 예산 대신 여유 공간 검사
   - 미디어 ID
   - 기존 실험 기대값으로 회귀 테스트(생성 fixture, 짧은 길이)
2. **타임라인 모델 v1:** 편집 연산과 실행 취소 명령. UI 없이 단위 테스트(독립 기대값).
3. **앱 셸:** SwiftUI 창 배치, 열기 패널·끌어 놓기 가져오기, 미디어 목록(썸네일·길이).
4. **타임라인 뷰:** 클립 그리기, 재생 헤드, 선택 → 분할 → 트림 → 이동 → 삭제 → 실행 취소 연결.
5. **프리뷰:** 편집 뒤 composition 재구성, 재생 헤드 유지, 재생 제어, 프레임 이동, 끝 유지.
6. **내보내기:** 저장 패널, 진행률 시트, 취소, 실패 안내, 대치 확인과 원자적 교체.
7. **검증:** 자동 테스트(§3의 1~6), 진단 분리 확인, 소유자 수동 체크리스트.

각 단계는 작게 나눠 빌드·테스트가 통과하는 상태로 진행한다. 실험(E2 결함 조사, E3-2 이후)은 별도 승인에 따라 나란히 진행할 수 있다.

## 7. M1에 실제로 영향을 주는 소유자 선택

1. **앱 코드 착수 승인:** 저장소에 Xcode 프로젝트와 앱 코드를 만드는 작업 승인. 지금 CLAUDE.md는 제품 앱 코드를 허용하지 않는다.
2. **UI 기술과 최소 macOS:** §5 권장(SwiftUI + AppKit, macOS 15 잠정)으로 시작할지. 최소 버전은 쓸 수 있는 SwiftUI·AVFoundation API를 바꾼다.
3. **타임라인 편집 의미:** M1을 리플(빈틈 없음, 영상 트랙 1개, 연결된 소리)로 시작할지, 처음부터 빈틈 있는 자유 배치로 할지. 자유 배치는 엔진 변경과 검증 범위가 커진다.
4. **M1 타임라인·내보내기 기본 설정:** 1920×1080, 30 fps, H.264/AAC MP4로 둘지. 출력 정책(O-03, O-04)은 미정이며, M1 값은 바꿀 수 있는 기본값으로 둔다.
5. **앱 샌드박스를 M1부터 켤지:** 켜면 미디어 접근·임시 파일 처리를 처음부터 맞추고, 끄면 개인 사용에는 간단하지만 배포 전에 다시 손봐야 한다.

나머지(단축키, 스냅, 오류 문구, 진단 메뉴 위치 등)는 승인된 범위 안에서 Claude Code가 정하고 기록한다.
