## 4. 이미 기록된 문제와의 관계

- **대기 알림 때문에 저장·열기 이어짐이 2 s 뒤 중단**: 새 계기 둘. 확인창 중 사용자가 ⌘N·⌘O를 누르면 "프로젝트를 바꿀 수 없습니다" 알림이 대기한다. 가져오기 거부·내보내기 결과 시트가 그때 뜰 수도 있다. 새 종류의 결과는 없다(멈춘 상태 없음).
- **끌기 중 초점 잃음(미확인)**: 새 결과. CP-01의 강제 종료 경로, 메뉴 저장이 끌던 중간 상태를 저장된 것으로 표시, 그동안 열기는 모두 "여는 중 편집됨"으로 포기, 재연결은 50 ms마다 계속 기다림.
- **항등 변형의 빈 실행 취소 단계**: 새 결과 없음(클립 생성 때 항등 변형을 없애므로 손으로 만든 파일에서만).
- 그 밖에 A-010 프레임 0 불일치, `ClipAudioTests` 실패, 간헐 자체 검사 실패, 실제 MP3 미검증, E2 문제는 기록 그대로다([ROADMAP.md](../ROADMAP.md) §S.6).

## 6. 검증 빈틈

- 붙여넣기: 원래 레인이 지워진 경우, 연결 짝이 묶음에 없는 경우, 미디어 종류가 맞지 않는 경우, 영상만 있는 클립, 레인을 만든 뒤 실패하는 경우, 붙여 넣은 결과의 렌더링 테스트가 없다.
- 엔진: 페이드 두 개 동시 지정(CP-09), 리플 지점에서 정확히 끝나는 다른 레인 클립(CP-10), `isValid` 거부 입력(CP-11), 내보내기 마무리 중 취소(CP-13), 낮은 표본률 믹스(CP-14) 테스트가 없다.
- 실제 쓰이는 레인 쌓기 함수는 `TransformTests`로만 시험하고, `testVisibleSegmentsTopLaneWins`는 이제 쓰지 않는 함수를 본다.
- [app/README.md](../../app/README.md) §20.3의 렌더링 표본 주장은 흔들리는 `ClipAudioTests`에 기대어 다시 재현할 수 없다.
- 실행해야 아는 것: CP-01·CP-03의 실제 발생 여부, 저장 패널 이름 칸의 ⌘A·⌘C·⌘V·⌘X, 선택만 가능한 정보 텍스트를 누른 뒤 단축키가 막히는지, 한국어 2벌식 텍스트 칸 ⌘C·⌘V(소유자 확인 때 입력 소스 기록 없음), 레인 이름 편집 중 다른 텍스트 칸을 누를 때 초점.

## 8. 리뷰 때 판단과 받아들인 일정

- 리뷰 판단: V·C 작업을 반드시 막을 결함은 없다. 다만 CP-01·CP-03은 V·C가 고칠 타임라인 마우스·끌기 경로와 키 처리에 걸친다.
- 소유자가 받아들인 일정(D-029): 이 리뷰는 수정 없이 기록 → 다음 기능은 단축키 목록 정리와 V·C 도구 → V·C 뒤, 자막 전에 안정화 체크포인트 → 그 체크포인트에서 CP-01·CP-02·CP-03과 CP-04를 우선. V·C 작업 중 고친 지적은 구체적 수정과 알맞은 검증이 있을 때만 닫는다.
