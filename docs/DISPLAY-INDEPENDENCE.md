# 화면 독립성 — 요구사항, 코드 감사, 검증 계획

> 작업: SP-EXPORT-E4D-DISPLAY-INDEPENDENCE-107 (2026-11-27, 문서 전용).
> - **확정(소유자 승인 2026-11-27):** §1의 제품 요구사항 [R-50](PRODUCT.md#51-소유자-승인-추가-요구사항)과 §2의 제품·진단 구분. 결정 기록은 [D-043](DECISIONS.md#2026-11-27-화면-독립성-제품-요구사항소유자-승인-sp-export-e4d-display-independence-107)이다.
> - **제안(소유자 미승인):** §3–§7의 감사 분류, 검증 행렬, 비교 기준, 후속 변경. 승인 전에는 수락 기준이 아니다.
> - 이번 작업에서는 앱 빌드·실행, ScreenCaptureKit, G4/G5, 화면 설정 변경, 소스·fixture·동결 모델 변경을 하지 않았다. 아래 코드 판단은 `feature/spectrum-effects` @ `d15bdf4` 소스를 **읽어서** 얻은 것이며 런타임 증거가 아니다.

## 1. 제품 요구사항 (R-50, 소유자 승인)

ON THE FRAME은 지원하는 macOS 화면 환경에서 올바르게 동작해야 한다. 사용자에게 특정 모니터·해상도·HiDPI 모드·backing scale·ICC 프로필을 고르라고 요구하지 않는다. 이것은 G4/G5 진단의 선호가 아니라 **필수 제품 요구사항**이다.

| 항목 | 필수 동작 |
| --- | --- |
| R-50.A | 지원하는 내장·외장 화면에서 앱이 실행되고 동작한다. |
| R-50.B | Retina/HiDPI와 비 HiDPI 모드(backing scale 1과 2 포함)에서 동작한다. |
| R-50.C | 편집기 컨트롤과 Preview가 사용할 수 있는 창·화면 크기에 맞춰진다. |
| R-50.D | 타임라인 편집, 오디오 재생, Spectrum, 자막이 화면과 관계없이 같은 방식으로 동작한다. |
| R-50.E | 열린 창을 화면 사이로 옮겨도 편집 상태가 손상되거나 사라지지 않는다. |
| R-50.F | 화면을 연결·분리해도 프로젝트 데이터나 미디어가 손상되지 않는다. |
| R-50.G | Preview 기하가 논리 좌표와 물리 화소 모두에서 정확하다. |
| R-50.H | 내보내기의 구성·시각·소리·Spectrum·자막 위치는 편집기를 띄운 화면에 의존하지 않는다. |
| R-50.I | 색 관리되는 Preview는 해당 화면의 색 특성을 반영한다. |

**요구하지 않는 것.** 서로 다른 모니터에서 물리 휘도나 raw 화면 RGB 값이 같을 필요는 없다. ICC 프로필, HDR 능력, 밝기, 색역이 다르면 보이는 모습이 달라질 수 있다. 제품이 보장할 것은 **같은 편집 의미**와 **적절히 색 관리된 Preview**다.

**내보내기 일관성의 판정.** 내용, 시각, 기하, 색 메타데이터, 지원하는 렌더링 허용 오차로 판단한다. MP4 파일 해시가 같아야 한다는 뜻이 아니다(§5).

## 2. 제품과 진단의 구분 (소유자 승인)

| 구분 | 내용 | 화면 변화의 의미 |
| --- | --- | --- |
| **제품** | R-50의 화면 독립 편집 요구사항. 프로젝트 좌표·내보내기는 출력 1920×1080 기준이며 화면에 묶이지 않는다. | 화면이 바뀌어도 편집 의미와 내보내기가 유지되어야 한다. |
| **진단** | G4/G5의 환경별 동결 보정(CAL-B)과 재표본화(RES-B) 모델. 출처에 화면 프로필 이름, backing scale, videoRect(화소), 앱 해시, 캡처 색 공간이 기록된다(`ModelProvenance.environmentMatches`). | 다른 환경은 **진단 전제 조건 실패**다. 제품이 그 화면과 호환되지 않는다는 증거가 **아니다**. |

- G4-04 모델(CAL-B `b32fbe20812841c5`, RES-B area)은 기록된 환경, 즉 내장 Liquid Retina XDR·backing scale 2·videoRect [780, 104, 960, 540]에서만 유효하다. **scale 1에서는 유효하지 않다.**
- 다른 환경에서는 새 G4 보정·재표본화 순서를 처음부터 실행한다. 호환되지 않는 환경 사이에서 모델을 재사용하지 않는다.
- 모델 출처 검사, 환경 지문 검사, G0 임계값(v1 `b2cd7ba0367c680d`), D-042 의존 순서(CAL-B → RES-B → RES-C), 첫 이상 정지 규칙은 약하게 하지 않는다. G0 색 계약 v3, D-041, D-042, 임계값 v1은 이번 작업에서 바꾸지 않았다.
- 진단용 화면 보정값은 프로젝트 설정이 아니다. 프로젝트 파일·UserDefaults·제품 렌더링 경로에 저장하거나 반영하지 않는다(현재 코드도 그렇다, §3 P-6).

## 3. 제품 코드 감사 (2026-11-27, 소스 읽기)

범위: `#if DEBUG`가 없는 앱 파일 20개(`ContentView`, `EditorLayout`, `PreviewOverlay`, `InteractivePreview`, `PausedSpectrumOverlay`, `PlaybackSpectrumController`, `SubtitlePreview`, `SubtitleUI`, `TimelineView`, `LaneZoom`, `ProjectStore` 등)와 엔진 `OnTheFrameEngine`(`RenderSettings`, `CompositionPlanner`, `ExportService`, `SubtitleExport`, `SubtitleRenderer`, `SpectrumRenderer`, `SpectrumExport`, `ImagePreviewMetal`, `InternalImagePreview`). `NSScreen`, `backingScaleFactor`, `contentsScale`, 화면 변경 알림, 색 공간, 고정 크기를 검색하고 해당 경로를 읽었다.

분류: **CONFIRMED** = 소스로 확인한 사실(의존 있음 또는 없음), **POTENTIAL RISK** = 코드상 가능성은 있으나 결함으로 확인하지 않음, **NOT VERIFIED** = 런타임 없이는 판단할 수 없음.

### 3.2 잠재 위험과 미검증 항목

| ID | 분류 | 내용 | 영향 |
| --- | --- | --- | --- |
| R-1 | POTENTIAL RISK | `contentMinSize`는 창을 붙일 때 그 화면의 `visibleFrame`으로 한 번만 정한다. 화면 이동이나 해상도 변경 뒤 다시 계산하지 않는다. | 최소 내용 크기 약 702×431 pt라 일반 화면에서는 영향이 작다. 작은 화면으로 옮길 때 최소 크기가 남을 수 있다. 편집 데이터에는 영향 없음. |

| R-5 | POTENTIAL RISK (겉모습) | 타임라인 일부 선이 0.5 pt 오프셋으로 그려진다(`TimelineView.swift:685·804`). scale 2에서는 선명하지만 scale 1에서는 흐려질 수 있다. | 편집 의미에는 영향 없음. |

| R-7 | NOT VERIFIED | 내보내기 결과가 화면과 무관하다는 것은 코드상 입력으로 확인했을 뿐이다(P-5). 서로 다른 화면에서 내보낸 두 결과를 비교한 적은 없다. | 행렬 §5 비교 필요. |

**제한적인 런타임 단서(수락 아님).** G5-01(2026-11-26, DEBUG G3-06 앱, 합성 fixture)의 `C builtin` 실행은 scale 1, videoRect [237, 52, 960, 540]에서 raw 관찰 38개를 PASS로 기록했다(identity, timing, dimensions, stability, export masks). 보정 의존 판정 12개는 모델 환경 불일치로 INCONCLUSIVE였다. 이것은 DEBUG 진단 한 장면의 관찰이며 제품 수락, 소유자 시험, R-50 충족 증거가 아니다.

### 3.3 감사 결론

- 제품 경로에서 backing scale 2 가정, 고정 화면 해상도, 정확한 Preview 창 크기 요구, 화면 화소 수를 내보내기 크기로 쓰는 경로, 현재 모니터에 묶인 프로젝트 좌표는 **찾지 못했다**(CONFIRMED 범위는 소스 읽기).
- 화면·배율 변경에 대한 명시적 반응이 없다는 점(R-1, R-2)은 결함으로 확인되지 않은 위험이다. 런타임 행렬 E·F·G로 판단한다.
- 진단 보정값을 영구 프로젝트 설정으로 오인하는 경로는 없다(P-6, 진단 모델은 외부 `Results/`에만 있다).

## 4. 진단 보정의 한계와 scale 1 G4 전략

### 4.1 진단 한계

| ID | 내용 |
| --- | --- |
| D-L1 | 환경 지문의 `displayProfile`은 **지역화된 이름**(예: "컬러 LCD")만 비교하고 ICC 바이트는 비교하지 않는다. 같은 이름의 다른 프리셋을 구분하지 못한다. 106의 외부 guard는 이름 별칭을 소유자 승인과 ICC 바이트 일치로만 허용한다. 지문을 약하게 하지 않으며, 보강은 별도 승인 대상이다. |
| D-L2 | videoRect 원점은 창 위치에 따라 정해진다. 화면 크기가 다르면 원점도 달라진다(scale 2: [780, 104], scale 1: [237, 52]). 같은 모드에서 G4와 G5를 따로 실행했을 때 원점이 0.01 px 안에서 재현되어야 한다. G4-04에서는 scale 2로 앱을 네 번 실행하는 동안 환경 검사가 통과했다. scale 1에서의 재현은 NOT VERIFIED다. |
| D-L3 | 106 guard(`display_guard.py`)는 동결 모델이 있어야 동작하는 G5 전용이다. 새 G4에는 비교할 모델이 없으므로 그대로 쓸 수 없다. |
| D-L4 | guard는 내장 화면 하나만 허용한다(T7). 외장 화면 진단에는 별도 설계가 필요하다. |
| D-L5 | 104에서 기록한 G5 위험(previewEdge NOT VERIFIED가 허용 목록에 없음, builtin 합성기 FAIL 정지 등)은 scale과 무관하게 남아 있다. |

**권고(제안).** 소스·runner·gate에서 막는 요인은 없다. 실행 전 관찰(①)을 정하면 **현재 scale 1에서 새 G4-05를 한 번 감독 실행**할 수 있다. 순서는 다음과 같다.

1. 실제 scale 1 환경을 읽기 전용으로 확인한다(화면 설정은 바꾸지 않는다).
2. 새 CAL-B를 scale 1에서 실행한다.
3. 그 동결 CAL-B로 CAL-V를 실행한다.
4. scale 1에서 새 RES-B를 확립한다.
5. 짝이 맞는 동결 모델로 RES-C를 실행한다.
6. G4 PASS 뒤에만, 그 scale 1 모델로 G5를 실행한다. 이때 scale 1 모델에 맞춘 실행 전 guard를 쓰고 `C builtin`부터 새 폴더에서 시작한다.

G4-04(scale 2) 모델과 증거는 보존하며 바꾸지 않는다. scale 1의 G4 PASS가 나와도 scale 2 결과를 대체하지 않는다. 각각 자기 환경의 진단 증거다.

**현재 scale 1 화면에서 가장 작은 다음 시험.** 진단 쪽은 위 G4-05 한 번(앱 실행 4회)이다. 제품 쪽은 §6 행렬 A의 소유자 수동 점검(지정 미디어 격리 사본)이다. 두 시험은 서로 대체하지 않는다.

### 5.2 비교 기준 (제안)

같은 앱 빌드, 같은 Mac, 같은 프로젝트 격리 사본으로 편집기를 화면 X에 둔 내보내기와 화면 Y에 둔 내보내기를 비교한다. **먼저 같은 화면에서 두 번 내보내 기준 변동을 잰다.** 화면 간 차이는 이 기준 변동과 비교해 판단하며 파일 해시는 쓰지 않는다.

| 항목 | 비교 방법 | 기대 |
| --- | --- | --- |
| 프레임 신원 | 디코딩한 각 프레임의 frame code 또는 장면 식별자 | 모든 프레임 일치 |
| PTS·길이 | 영상 PTS 목록, 프레임 수, 트랙 길이 | 정확히 일치(30 fps CFR) |
| 구성 크기 | 트랙 자연 크기, 변환, 화소 형식 | 1920×1080, 같은 값 |
| Spectrum 시각·위치 | 표본 프레임의 Spectrum 마스크 경계 상자와 막대 높이 | 같은 화면 기준 변동 이내 |
| 자막 시각·위치 | 처음·마지막 표시 프레임, 경계 상자 | 프레임 단위 일치, 상자는 기준 변동 이내 |
| 소리 시각 | 디코딩한 PCM 상호상관 지연, 길이, 표본률·채널 | 지연 0, 길이 같음, RMS 차이는 기준 변동 이내 |
| 색 메타데이터 | 원색·전달 함수·행렬·범위 태그 | BT.709 태그 같음 |
| 화소 출력 | 디코딩한 Y/CbCr 평면의 최대·평균 절대 차이 | 같은 화면 기준 변동 이내. 기준을 넘는 차이는 허용 오차를 정당화하기 전까지 조사 대상이며 자동 수락하지 않는다. |

도구: FFmpeg 등 새 의존성은 설치하지 않는다. 기존 AVFoundation 기반 DEBUG 비교(parity 판정, `OTFDevSupport/FrameCompare.swift`)를 다시 쓸지, 새 비교기를 만들지는 별도 승인이 필요하다.
